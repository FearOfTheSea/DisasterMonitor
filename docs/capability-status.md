# Capability and promotion status

This page is the release-evidence authority. Code availability, automated tests,
and normative promotion are separate claims.

- **Implemented**: A bounded production path exists with stated authority and
  fallback.
- **Automated passing**: Repository fixtures and fault injections pass. This does
  not prove external validity or human utility.
- **Promotion passed**: The declared external or human evidence exists and passed.
- **Promotion pending**: Required evidence is absent. Repository fixtures cannot
  replace it.
- **Unsupported**: No production path is claimed.

Volcanic-eruption discovery uses a bounded primary Smithsonian/GVP path. Its
preliminary WVAR coverage and source limits remain explicit. They do not imply
complete global surveillance or impact evidence.

## Evidence rules

Promotion-pending evidence requires locked provenance, checksums, rights, study-local
identities, and the evaluator named by the relevant family.

Synthetic data, LLM judges, simulated participants, and repository-authored labels
do not satisfy external or human gates. Missing benchmark, licensing, ethics,
participant, pilot, or recovery evidence fails closed.

Until promotion, the bounded implementation and its fallback remain active.

Incident Watch v1 is implemented and automatically tested for deterministic change
classification, idempotency, queue retry, in-memory and PostgreSQL persistence, HTTP
contracts, and in-app timeline behavior.

Operator Agent v1 adds bounded, typed assistant proposals for opening existing
panels, changing the display window, showing existing map layers, and requesting a
confirmed Incident Watch. Automatic UI actions remain reversible presentation
changes; watch creation remains confirmation-required and uses the existing bounded
watch policy. The agent cannot invent providers, URLs, layers, scopes, or watch
intervals.

These tests demonstrate the bounded local mechanism. They do not demonstrate provider
completeness, timely global detection, alert usefulness, or operational response
outcomes.

Those claims remain promotion-pending. They require locked live episodes and
supervised human evaluation.

The situational-awareness frontend adds a typed registry for existing map layers,
display-only time filters and presets, and inspectable layer provenance and limits.
It also adds visible Active Incidents coverage and freshness transport data,
point-marker clustering, and a deterministic Findings center.

Findings aggregate returned watch changes, coverage states, warnings, and
compound-hazard correlations. They do not create facts, rankings, alerts,
provider-health guarantees, causal claims, or consequential recommendations.

These presentation changes do not strengthen the OP promotion claim.

P1 operational awareness adds an informational Source Catalog, dataset-specific
hidden-tab-aware polling, bounded shareable presentation URL state, and deterministic
regional navigation.
It also adds a keyboard-only in-memory command index and a dedicated NOAA/NWS
alert-artifact layer.

The alert adapter is bounded and automatically tested for CAP fields,
expiry/cancellation, exact-or-missing geometry, empty and failure coverage, and
separation from physical incidents.

This does not establish global warning coverage, delivery timeliness, public-warning
utility, impact prediction, evacuation utility, or a physical disaster event.

Compound Hazard Correlation v1 and cyclone supplemental map layers are implemented as
bounded descriptive context with deterministic fixture coverage.

The correlation supports only the documented earthquake/landslide and
tropical-cyclone/flood point and time gates. It does not perform causal inference.

The cyclone layer distinguishes provisional IBTrACS points from NHC/CPHC forecast
tracks and uncertainty cones.

These automated paths do not demonstrate causal validity, prediction accuracy,
global forecast completeness, warning authority, impact prediction, population
exposure, or evacuation utility.

Run the relevant evaluator from the repository root:

```powershell
uv run --directory apps/api pytest -q tests/evaluation
```

Multimodal preparation and operator-study commands are documented in
[multimodal-awareness.md](multimodal-awareness.md).

## Unsupported

Automatic imagery retrieval, generic live weather, forecasting, radar, geocoding,
arbitrary source crawling, automatic source trust promotion, and hosted models remain
unsupported.
Production authentication/TLS, multi-user persistence, cloud deployment, public
warnings, evacuation directives, and resource orders also remain unsupported.

Email, SMS, browser/OS push, and externally routed Incident Watch notifications also
remain unsupported.
